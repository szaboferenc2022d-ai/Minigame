    Playwright telepítése

    A Playwright egy valódi böngészőt (Chromium, Firefox, WebKit) indít, és kódból kattintgat benne, ahogy egy felhasználó tenné. A telepítő mindent előkészít: a csomagot, a beállításfájlt, egy mintatesztet és egy GitHub Actions munkafolyamatot.

    terminála telepítő futtatása

    1. Hozz létre egy külön ágat a tesztekhez, hogy a main tiszta maradjon: 
      git switch -c testing
    2. A projekt gyökerében indítsd el a Playwright telepítőjét: 
      npm init playwright@latest
    3. A kérdésekre így válaszolj:
      • Nyelv: JavaScript
      • A tesztek mappája: tests (az alapértelmezett)
      • GitHub Actions munkafolyamat hozzáadása: igen
      • Böngészők telepítése: igen (ez néhány percig is eltarthat)

    ellenőrzésmit hozott létre a telepítő?

    Ezeket a fájlokat nem kell kézzel megírnod, de érdemes átnézni őket:

    • package.json: két új fejlesztési függőség, a @playwright/test és a @types/node.
    • playwright.config.js: a tesztfuttató beállításai. Ezt a következő fejezetben a saját játékunkhoz igazítjuk.
    • tests/example.spec.js: két mintateszt, amelyek a playwright.dev oldalt nyitják meg, nem a mi játékunkat.
    • .github/workflows/playwright.yml: GitHubon minden push után lefuttatja a teszteket (a 4. fejezetben részletezzük).
    • .gitignore: kiegészül a test-results/ és playwright-report/ mappákkal. Ezek a futtatás kimenetei, nem kerülnek a gitbe.
    tests/example.spec.js – a generált mintateszt

      A két mintateszt mindhárom böngészőben lefut, ez összesen 6 teszt.

    Az első játéktesztek

    Két tesztet írunk: az egyik megszámolja a tábla mezőit, a másik ellenőrzi, hogy bal klikkre X, jobb klikkre O kerül a mezőbe. A mezőket a square CSS-osztály alapján találjuk meg.

    törléstests/example.spec.js

    A mintatesztekre már nincs szükség. Töröld a fájlt.

    új fájltests/game.spec.js

    1. Az első sor legyen // @ts-check (így a szerkesztő jelzi a típushibákat), majd importáld a test-et és az expect-et a @playwright/test-ből.
    2. Minden teszt előtt nyisd meg a játékot. A test.beforeEach egy közös előkészítő lépés, ami minden teszt előtt lefut, így minden teszt üres táblával indul: 
      test.beforeEach(async ({ page }) => {
  await page.goto('/');
});
    3. Első teszt ('the board has 9 squares'): kérd le a mezőket egy lokátorral: page.locator('.square'). Ellenőrizd, hogy pontosan 9 ilyen elem van: toHaveCount(9).
    4. Második teszt ('players take turns'):
      • Kattints bal gombbal az első mezőre (squares.nth(0).click()), olvasd ki a szövegét a textContent()-tel, és ellenőrizd, hogy 'X'.
      • Kattints jobb gombbal a második mezőre, majd ellenőrizd, hogy 'O' lett: 
        await squares.nth(1).click({ button: 'right' });

    Miért kell az await? Minden böngészőművelet (megnyitás, kattintás, kiolvasás) időbe telik, és ígéretet (Promise) ad vissza. Ha lemarad az await, a teszt nem várja meg a kattintást, és véletlenszerűen bukik el.

    Tipp: a textContent() + toEqual páros egyszer olvas, és nem vár. Biztosabb a Playwright „webes” ellenőrzése, ami pár másodpercig újrapróbálkozik, amíg a feltétel teljesül: await expect(squares.nth(0)).toHaveText('X');

    Tesztek a GitHubon

    A telepítő által létrehozott munkafolyamat (CI) minden pushnál egy tiszta Ubuntu gépen telepíti a projektet, és lefuttatja a teszteket. Ezt a fájlt nem kell módosítanod, de érdemes megérteni, mert a playwright.config.js több beállítása is ehhez igazodik.

    ellenőrzés.github/workflows/playwright.yml

    1. Mikor fut? Ha a main vagy master ágra pusholsz, illetve ha ezekre nyitsz pull requestet. A testing ágra pusholva még nem fut, csak a PR megnyitásakor.
    2. Mit csinál? Letölti a kódot, telepíti a Node.js-t, npm ci-vel telepíti a függőségeket, letölti a böngészőket, majd lefuttatja az npx playwright test parancsot.
    3. Riport: a futás végén a playwright-report mappát feltölti artifactként. A GitHub Actions fülön 30 napig letölthető, akkor is, ha a teszt elbukott.
    .github/workflows/playwright.yml – a generált munkafolyamat 
    name: Playwright Testson:  push:    branches: [ main, master ]  pull_request:    branches: [ main, master ]jobs:  test:    timeout-minutes: 60    runs-on: ubuntu-latest    steps:    - uses: actions/checkout@v4    - uses: actions/setup-node@v4      with:        node-version: lts/*    - name: Install dependencies      run: npm ci    - name: Install Playwright Browsers      run: npx playwright install --with-deps    - name: Run Playwright tests      run: npx playwright test    - uses: actions/upload-artifact@v4      if: ${{ !cancelled() }}      with:        name: playwright-report        path: playwright-report/        retention-days: 30

    ellenőrzésa process.env.CI ágak a configban

    A GitHub Actions beállítja a CI környezeti változót, ezért ott a config másként viselkedik:

    • forbidOnly: ha bent felejtettél egy test.only-t, a CI-futás hibával leáll, így nem marad ki csendben a többi teszt.
    • retries: 2: a CI-n egy elbukott tesztet még kétszer újrapróbál. Ha a második próbálkozás sikerül, a teszt „flaky”, vagyis instabil.
    • workers: 1: a CI-n egymás után futnak a tesztek, a kevés processzormag miatt.
    • reporter: 'html': ezt a riportot tölti fel a munkafolyamat.
    • trace: 'on-first-retry': újrapróbáláskor nyomkövetést rögzít, ezt a riportban lépésenként visszanézheted.
    • reuseExistingServer: false: mindig saját Vite szervert indít.

    Ellenőrzés: pushold a testing ágat, és nyiss róla pull requestet a main-re. A PR alján megjelenik a Playwright Tests ellenőrzés, és pár perc múlva zöld pipára vált.

    Kitekintés: további tesztek

    Az építési útmutató minden lépésének van egy „Ellenőrzés” sora. Ezek jó kiindulópontok automatikus tesztekhez. Írj mindegyikhez egy új test(...)-et a game.spec.js-be.

    Lehetséges tesztek

    • Ugyanaz a játékos nem léphet kétszer: két bal klikk két különböző mezőre. A második mező üres marad: await expect(squares.nth(1)).toHaveText('');
    • Foglalt mező: bal klikk a 0. mezőre, majd jobb klikk ugyanoda. A mezőben továbbra is X áll.
    • Győzelem: rakd ki az X-et a 0, 1, 2 mezőkre (közben O a 3-ra és 4-re), és ellenőrizd az üzenetet: await expect(page.getByText('Game over! X won')).toBeVisible();. Győzelem után a további kattintások ne változtassanak semmin.
    • Döntetlen: töltsd ki a táblát nyerő hármas nélkül, és keresd a Draw! No winner szöveget.
    • Újrakezdés: egy lezárt játék után kattints a gombra (page.getByRole('button', { name: 'Reset' })), és ellenőrizd, hogy mind a 9 mező üres.
    • Utolsó lépés kiemelése: lépés után a mezőn legyen lastcell osztály: await expect(squares.nth(0)).toHaveClass(/lastcell/);, a következő lépés után pedig már ne legyen rajta.
    • Ismétlődő lépések: ha sok tesztben kell lépni, írj egy segédfüggvényt, például play(squares, [0, 3, 1, 4, 2]), ami felváltva bal és jobb klikkel kattint a megadott mezőkre.

    Tipp: a npx playwright codegen http://localhost:5173 megnyit egy böngészőt, és a kattintásaidból tesztkódot generál. Jól jön, ha nem tudod, milyen lokátort használj.

    Kész a tesztkészlet. Minden új funkcióhoz írj egy tesztet is!
